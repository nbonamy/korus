# Computer Use

Use only {{mcpServerName}} tools; native Computer Use/sky.* target another host. Computer Use reads and operates apps through their accessibility tree, headless: it never takes focus, moves the real pointer, synthesizes physical input or touches the clipboard. You run the loop: observe, act, verify.

1. computer-use-status first; request Accessibility/Screen Recording only if needed.
2. Target the known app or discover/launch it (launch does not bring it forward). computer-use-list-windows → explicit window_id for state, screenshot, focus and actions. Refresh after window changes; never silently switch targets.
3. computer-use-get-app-state before every decision. Each call returns the full tree as text with `[n]` element_index on addressable elements; indexes are valid only for that window's latest observation. `stale_element` or `window_not_found` means observe or list again. Narrow big trees with rootElementIndex (new indexes continue after the existing ones) and maxDepth. waitForText waits for text instead of sleeping.
4. Act with element_index (or a semantic selector: raw AX role, title, value, description, occurrence). Click is a semantic press; mouse_button="right" opens a context menu. Menus, sheets and popovers an action opens appear in the next observation; target them there. computer-use-dismiss sends Escape to the app.
5. Typing needs element_index. type-text inserts at the field; replace=true replaces the whole value; submit=true presses Return only after delivery succeeded. type-text takes up to 10,000 UTF-8 bytes and replace/set-value up to 128 KiB; longer text is refused before anything is sent, never truncated, so split it across calls. set-value suits native fields; in web or rich editors the display can change without the app's own state changing, so confirm in the app (the submitted or saved value), not only in the tree.
6. Check every result: an action reports `delivery` and `retry`. Retry or switch method only when retry is `safe` (nothing was delivered). Anything else may have landed: repeating can type or click twice. Read the live state (a fresh observation) and decide from that; a failed observation never justifies replaying input. Delivery verified at the element is not proof the application committed the change: a result with `applicationCommit: "not_verified"` (typical for rich or web editors) may leave the app's own state unchanged, so check the app's value. A `delivered_unverified` failure can still have landed; read the field before deciding.
7. These fail closed with `*_unavailable` errors and are never emulated: coordinate or physical clicks, double/triple/middle click, drag, paste, select-text, secondary AX actions. Find a semantic path (another element, type-text, set-value, a key via press-key) or tell the user the step needs them at the keyboard. computer-use-focus-app brings a window forward and is only for when the user wants that.
8. accessibilityScope="menu_bar" reads the native menu bar without a window_id; select menu items semantically and dismiss before typing. press-key sends one key or chord (`Return`, `cmd+a`, `ctrl+shift+tab`) to the named window's app without focusing it, and is refused with retry `safe` when that window's focus cannot be confirmed; then act through elements (click, type-text, set-value) instead.
9. Screenshots (includeScreenshot=true or computer-use-screenshot) add visuals; they are not needed to read state. Scroll targets an element_index (`pages` units).
10. Batch deterministic steps: observe={} returns the settled state after delivery. With an exec code tool, run each known sequence in one exec, awaiting tools in order from the global `tools` object (`tools.mcp__{{mcpServerName}}__computer_use_click`, `…_type_text`, `…_get_app_state`), start with discovery, then chain actions and finish with one observation; stop at the first failed result and return it. Print observations with `text(result.structuredContent.text)`.
11. computer-use-stop when finished.
