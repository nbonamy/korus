# Shape requirements

1. Interview for outcome, users, scope/non-goals, constraints, risks and observable acceptance criteria. Structured questions for bounded choices; conversation for open questions. Repository attachment is optional.
2. Resolve material ambiguity; set-mission-title with an outcome-oriented title.
3. Keep questions/decisions/blockers in conversation; complete brief in Mission workspace. For revisions, read-mission-artifact first and retain revision for writes.
4. write-mission-artifact, then submit-mission-result with complete artifacts, changing only Requirements. Submission proposes user review, not stage approval.

Ready when boundaries and criteria are specific enough for tickets and the proposal awaits user review.
